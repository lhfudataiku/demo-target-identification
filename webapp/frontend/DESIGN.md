# Dataiku webapp design system

How the team's DSS webapps look, written for coding agents and the people who review their
work. The front matter above is generated from the UI/UX team's `@dataiku/ea-ui-kit` theme
(`style/rfx.css`), which is itself generated from the Figma design system. Do not edit the
tokens here: a token change is a kit change. Edit the prose when the rules change.

Where things come from:
- **Components:** `@dataiku/ea-ui-kit`, every shadcn-vue primitive re-skinned by the UI/UX
  team. Browse them in the Storybook before writing markup.
- **Icons:** `@dataiku/vue-icons`, the DSS icon set (944 icons, `currentColor`).
- **App shell and helpers:** `bs-blueprint` (`AppLayout`, `PageHeader`, `SelectField`,
  `SettingsSwitchItem`, `EmptyState`, `StatusBadge`, `apiUrl`, `useThemeColors`).
- **Checks:** `npx bs-blueprint check` (doctor, lint, typecheck) enforces everything below.

## Overview

Internal tools for data scientists and analysts: dense, calm, and predictable. The interface
should read like a Dataiku product, not like a marketing site. One accent color carries every
interactive element; everything else is neutral. Content sits in bordered cards, navigation
lives in a tinted left sidebar that collapses to an icon rail, and there is no decoration that
does not carry information.

## Colors

The palette is the kit's: a neutral ramp, the Dataiku indigo as `primary`, a light blue
`secondary` and `sidebar`, and status colors. Every color is a token exposed to Tailwind as
`bg-<name>`, `text-<name>`, `border-<name>`. Tailwind's default palette is not part of the
theme: `bg-blue-500` is an unknown class and the lint rejects it.

- **Primary (`primary`):** buttons, active navigation, links, focus. Use it for the one most
  important action on a screen.
- **Surfaces:** `background` for the page, `card` for content containers, `popover` for
  floating surfaces, `muted` for header strips and subdued fills (`bg-muted/30`), `accent`
  for hover and selected rows, `sidebar` for the navigation column.
- **Text:** `foreground` for body text, `muted-foreground` for captions and secondary text.
  Each surface has a matching `*-foreground`.
- **Status:** `destructive` for errors and dangerous actions, `info` for neutral notices,
  `success` and `warning` (added by bs-blueprint until the kit ships them). For a pill use
  `<StatusBadge status="success">`; for text use `text-success`.
- **Charts:** `chart-1` to `chart-5`, read at runtime with `useThemeColors()` when a chart
  library needs raw values.
- **Lines:** `border` for borders and dividers, `input` for input outlines, `ring` for focus.

Dark mode is the kit's `.dark` class. Apps call `useThemeMode('light')` once in `App.vue` (light by
default, the user's choice stored in the browser) and expose `isDark` as a switch in Settings.
Never use `bg-white` or `text-white`: they ignore the theme and break dark mode.

## Typography

Source Sans Pro, bundled by the kit. Sizes follow Tailwind's scale plus the kit's heading
utilities and one addition from bs-blueprint, `text-2xs` (11px), for table captions and
metadata; use it instead of an arbitrary `text-[11px]`.

- **Page titles:** `PageHeader` (`text-xl font-semibold tracking-tight`).
- **Section titles:** `heading-md` or `text-sm font-semibold`, often uppercase with
  `tracking-wide` on card header strips.
- **Body:** `text-sm` on `foreground`.
- **Captions and metadata:** `text-xs` or `text-2xs` on `muted-foreground`.
- **Identifiers:** `font-mono text-xs` for dataset names, ids, and code.

## Layout

The kit's sidebar on the left (16rem, collapsing to a 3rem icon rail with ⌘/, a sheet below
768px), a content pane that scrolls on its own, and a 64px `PageHeader` pinned at the top of
the pane. Content is centered with `max-w-5xl` and 32px padding. Spacing follows an 8px unit:
4 for tight gaps, 8 between related controls, 16 inside cards, 24 between cards, 32 for page
padding. Use Tailwind's default spacing utilities; the `spacing` tokens document the intent.

## Elevation & Depth

Flat. Hierarchy comes from borders and tonal layers, not shadows: cards are `bg-card` with a
1px `border`; header strips inside cards are `bg-muted/30`; the sidebar is a tinted surface.
Shadows are reserved for floating surfaces (popovers, dropdowns, dialogs), where the kit
components already apply them.

## Shapes

The kit's radius (`--radius: 0.5rem`): `rounded-lg` for cards, tables, and dialogs;
`rounded-md` for inputs and buttons; `rounded-full` for pills and avatars. Never mix sharp and
rounded corners in the same view.

## Components

Components come from `@dataiku/ea-ui-kit` and are never copied into the app. Pages compose
them; they never restyle them. If a variant is missing, ask for it upstream (see
`docs/upstream.md` in bs-blueprint) rather than adding class lists in pages.

- **Buttons:** `Button` variants `default`, `secondary`, `outline`, `ghost`, `destructive`,
  `link`; sizes `sm`, `default`, `lg`, `icon`.
- **Inputs and selects:** `Input`, `Textarea`, `Switch`, `Checkbox`, the `Select*` parts;
  `SelectField` from bs-blueprint for the common options-array case.
- **Cards:** `Card` parts, or `rounded-lg border bg-card` with an optional `bg-muted/30`
  header strip carrying an uppercase `text-xs` title.
- **Badges:** `Badge` for labels; `StatusBadge` for status (`success`, `warning`,
  `destructive`, `info`, `muted`).
- **Page header:** `PageHeader` with `title`, `description`, and an `actions` slot.
- **Empty states:** `EmptyState` with an icon, title, description, and a call to action.
- **Sidebar:** `AppLayout` builds the navigation from Vue Router route metadata
  (`meta: { title, icon, menu, order, group }`); never hand-build menu arrays. Primary routes
  sharing a `group` render under that label; a route with `menu: 'new'` becomes the subtle
  "+" action beside its group's label (the kit's `SidebarGroupAction`), never a big button.
- **Brand block** (top of the sidebar, the kit's Storybook "Sidebar / Default" header, verbatim):
  a 32px rounded tile (`size-8 rounded-lg bg-sidebar-primary text-sidebar-primary-foreground`)
  holding a 16px icon from `@dataiku/vue-icons`, then the app name in `text-sm font-semibold`
  and a one-line subtitle in `text-xs`. Apps pass `appName`, `appSubtitle`, `appIcon` to
  `AppLayout` and never restyle the block. No logo image files.
- **Tables:** the kit's `Table*` parts inside a `ScrollArea`; sort helpers from bs-blueprint.
- **Toasts, dialogs, tooltips, tabs, dropdowns:** the kit's parts, as documented in Storybook.

## Do's and Don'ts

- Do use only token-backed utilities: `bg-card`, `text-muted-foreground`, `border-border`.
- Don't write hex, rgb, or hsl values in components, inline styles, or arbitrary classes such
  as `text-[#3b4e8c]`.
- Don't use `bg-white` or `text-white`; use `bg-card` and `*-foreground` so dark mode works.
- Don't use arbitrary values (`text-[13px]`, `w-[160px]`); pick the nearest scale step.
- Do reserve `primary` for interactive elements and status colors for status.
- Don't add a component or icon library, and don't copy components into the app.
- Do call `apiUrl()` on every API path; bare `fetch('/api/...')` breaks in DSS.
- Do run `npx bs-blueprint check` and fix every error before declaring frontend work done.
